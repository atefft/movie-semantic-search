StopServicesDevContainer

#248 — Add --using-dev-container flag to stop-services.sh

Spec for the --using-dev-container flag in stop-services.sh — disconnects the dev container from the compose network before teardown so Docker can remove the network cleanly.

Overview

stop-services.sh currently runs docker compose down without accounting for a dev container that may be attached to the compose project network. Docker will not remove a network that still has active endpoints, so if a dev container is connected (either by a prior ./start-services.sh --using-dev-container or a manual docker network connect), the teardown will fail to remove the network. This component extends stop-services.sh with a --using-dev-container flag that, when present, disconnects the dev container from the compose network before running docker compose down or docker compose down -v. The disconnect is a silent no-op if the container is not currently connected or if the network does not exist.

Data Contract

PropertyTypeDescriptionBehavior
--using-dev-container CLI flag Signals script is running inside a dev container Optional. Combinable with --clean in any order. When present: disconnect step runs before docker compose down. When absent: existing behavior unchanged.
--clean CLI flag Requests full teardown including volumes Optional. Unchanged from prior behavior. Combinable with --using-dev-container.
Exit code integer Script exit status 0 on success. Non-zero on: docker compose failure, unrecognised flag. The disconnect step never causes a non-zero exit.
Usage line stderr string Printed on unrecognised flags Updated to: Usage: stop-services.sh [--clean] [--using-dev-container]

For this repo the network is movie-semantic-search_default. This matches the approach used in the sibling feature #247 for start-services.sh.

Implementation Sketch

Flag parsing addition (extend existing for loop)

USING_DEV_CONTAINER=false for arg in "$@"; do case "$arg" in --clean) CLEAN=true ;; --using-dev-container) USING_DEV_CONTAINER=true ;; *) echo "Usage: stop-services.sh [--clean] [--using-dev-container]" >&2; exit 1 ;; esac done

Disconnect block (insert before the if [ "$CLEAN" = true ] block)

if [ "$USING_DEV_CONTAINER" = true ]; then COMPOSE_NETWORK="$(basename "$(pwd)")_default" DEV_CONTAINER_ID="$(cat /etc/hostname)" docker network disconnect "$COMPOSE_NETWORK" "$DEV_CONTAINER_ID" 2>/dev/null || true fi

Unit Test Checklist

  • --using-dev-container accepted without error (exit 0, no "Usage:" in output)
  • --using-dev-container --clean accepted without error (exit 0, no "Usage:" in output)
  • --clean --using-dev-container accepted without error (exit 0, no "Usage:" in output)
  • When --using-dev-container present and disconnect succeeds: exit 0, "Volumes preserved" in output
  • When docker network disconnect exits non-zero: script continues and exits 0 (no-op)
  • When --using-dev-container absent: docker network disconnect is NOT called
  • Usage line (on unrecognised flag) contains --using-dev-container
  • All existing tests (default mode, --clean, compose failure, V1 fallback, V2 preferred) continue to pass
Testing /etc/hostname: Because /etc/hostname cannot be overridden in shell unit tests without a mock cat, the implementation sets DEV_CONTAINER_ID="$(cat /etc/hostname)" once in the --using-dev-container block. Tests verify the disconnect call fires by intercepting docker network disconnect in the mock docker binary and asserting it is invoked. The exact container ID value in tests is whatever /etc/hostname contains in the test environment (a valid short ID if running inside a container).
