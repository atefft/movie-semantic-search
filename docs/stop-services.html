stop-services.sh

#204 — Add stop-services.sh — single entry-point to stop all services

Shell script at the repository root that stops all running Docker Compose containers. By default it preserves volumes for a fast restart; the --clean flag performs a full teardown including volumes.

Overview

stop-services.sh wraps docker compose down with two modes of operation. Without flags it runs docker compose down, leaving named volumes intact so that a subsequent ./start-services.sh can restart quickly without re-loading model artifacts or re-populating the database. With --clean it runs docker compose down -v, destroying all named volumes (qdrant_data, model-repository, data) and requiring ./start-services.sh --rebuild to restore them. The script exits non-zero with a clear error message if the underlying docker compose down command fails, and prints a usage line and exits non-zero for any unrecognised flag.

Flags

FlagCommand runDescription
(none) docker compose down Stop and remove containers. Named volumes are preserved. Prints a confirmation that volumes were preserved and that ./start-services.sh can be used to restart quickly.
--clean docker compose down -v Full teardown: stop containers and destroy all named volumes. Prints a warning that volumes (embeddings, model artifacts, database data) have been removed and that ./start-services.sh --rebuild will be required next time.

Data Contract

PropertyTypeDescriptionBehavior
Exit code integer Exit code of the script 0 on success; non-zero if docker compose down fails or an unrecognised flag is supplied
stdout string Status and error messages See message formats below

Message Formats

EventMessage
Default mode success Confirmation that services have stopped and volumes are preserved; instructs user to run ./start-services.sh to restart
--clean mode success Warning that volumes (embeddings, model artifacts, database data) have been removed; instructs user to run ./start-services.sh --rebuild next time
docker compose down fails Clear error message indicating failure; exits non-zero
Unrecognised flag Usage line (e.g. Usage: ./stop-services.sh [--clean]); exits non-zero

Observable Output Examples

$ ./stop-services.sh [docker compose output...] Services stopped. Volumes preserved — run ./start-services.sh to restart quickly.
$ ./stop-services.sh --clean [docker compose output...] WARNING: Volumes removed (embeddings, model artifacts, database data). Run ./start-services.sh --rebuild next time to restore them.
$ ./stop-services.sh --unknown Usage: ./stop-services.sh [--clean] $ echo $? 1

Unit Test Checklist

Shell scripts have no Python unit tests. All behavior is verified by the integration test suite. The observable contract above defines what integration tests must assert:

  • Default mode: exit code 0; stdout confirms volumes are preserved and instructs user to run ./start-services.sh
  • --clean mode: exit code 0; stdout warns that volumes (embeddings, model artifacts, database data) have been removed and instructs user to run ./start-services.sh --rebuild
  • docker compose down fails: exit code non-zero; stdout contains a clear error message
  • Unrecognised flag: exit code non-zero; stdout contains a usage line; docker compose is not invoked
