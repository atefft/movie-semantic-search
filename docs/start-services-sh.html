start-services.sh

#203 — Add start-services.sh — single entry-point to start all services

Bash script at the repo root providing a single entry point for the service lifecycle — fast default path and full-rebuild path.

Overview

start-services.sh is a Bash script at the repository root that provides a single entry point for the service lifecycle. It has two modes: a fast default path (./start-services.sh) that brings up containers using existing images and volumes, polls until all three services are healthy, and prints access URLs; and a full-rebuild path (./start-services.sh --rebuild) that wipes containers, volumes, locally-built images, and model/data files, then runs the complete pipeline from scratch. The script validates that .env exists before doing any Docker work, enforces a configurable health-check timeout, and exits non-zero with a clear message on any failure.

Data Contract

PropertyTypeDescriptionBehavior
(no flag) mode Default fast path Runs docker compose up -d then polls all services healthy, then prints URLs
--rebuild mode Full clean rebuild path Prints warning, requires "yes" confirmation, wipes everything, runs pipeline
unrecognised flag exit Any other argument Prints usage line to stderr, exits 1
HEALTH_TIMEOUT env var (integer, seconds) Max seconds to wait for all services to become healthy Default: 120; overridable at invocation: HEALTH_TIMEOUT=60 ./start-services.sh
.env file file presence Must exist in working directory Checked via [[ -f .env ]] before any docker calls; exits 1 with helpful message if absent

Dependencies

Health endpoints polled (default path + post-up in rebuild)

triton → http://localhost:8000/v2/health/ready qdrant → http://localhost:6333/healthz api → http://localhost:8080/api/operator/health
Poll interval: 5 seconds between retries. HEALTH_TIMEOUT (default 120 s) is the total wall-clock budget for all three services to become healthy.

docker compose down --rmi local -v (--rebuild only)

ScenarioTagBehaviorNotes
Success happy Exits 0, containers + volumes + local images removed --rmi local removes only locally-built images (api, pipeline); pulled images like triton/qdrant are preserved
No running containers happy Exits 0 (no-op) Safe to run on a clean machine
Failure error Script propagates exit code Rebuild aborted; set -euo pipefail handles propagation
--rmi local vs --rmi all: Use --rmi local to avoid re-pulling large pulled images like the Triton server (~10 GB). Only the locally-built api and pipeline images are removed and rebuilt.

docker compose run --rm load-model / load-data (--rebuild only)

ScenarioTagBehavior
Success happy Exits 0; next phase begins
Non-zero exit error Script exits 1 with phase name in error message, e.g. "load-model phase failed — aborting"

File Cleanup in --rebuild

To match make clean semantics, --rebuild removes these files before running the pipeline (in addition to docker compose teardown):

Edge Cases

Unit Test Checklist

Since this is a shell script, tests are verified via bash -n (syntax check) and targeted invocation with controlled inputs:

  • bash -n start-services.sh exits 0 (no syntax errors)
  • Missing .env: exits 1, stderr/stdout contains "not found"
  • Unrecognised flag --foo: exits 1, output contains "Usage"
  • --rebuild with input "no": exits 1 (aborted without docker calls)
  • --rebuild with input "yes": proceeds past confirmation (docker calls will fail in unit context — acceptable)
  • HEALTH_TIMEOUT is read from environment when set
